## Reproduce

Use Node 22.13 or later (Node 24 recommended). Copy `.env.example` to `.env` and supply your own configuration; never commit credentials.

```sh
npm ci
npm run test:regression
npm run build
```

The static build reads the existing Sanity production dataset and therefore needs network access. Content changes in Sanity can change generated HTML even when application code is unchanged.

Local-only posters, design experiments, screenshots and reports are excluded from Git. `public/.assetsignore` separately prevents design drafts from being published as web assets.

## Release procedure

1. Review the diff, run regression tests, and build from the intended commit.
2. Record the current Cloudflare production version as a rollback point.
3. Deploy only after approval, using the existing `wrangler.jsonc` production target; retain dashboard variables.
4. Verify the custom domain, application asset fingerprints, Story opening, Map navigation and return to Home.
5. Synchronize the tested source to `main` and retain an annotated release tag that records the deployed version.

The existing non-main branch workflow publishes to the separate preview Worker, not production. Do not treat a preview deployment as a production release.

## Dependency audit follow-up

The dependency audit at source synchronization reported 31 advisory entries (2 low, 10 moderate, 18 high, 1 critical). These packages were already present in the release lockfile; adding explicit test dependencies did not upgrade runtime dependencies. The critical entry is `tar`, reached through Sanity CLI/export tooling. This static deployment does not execute that CLI in visitor requests, but development/CI dependency maintenance still needs a separate reviewed update. Do not use a force-upgrade as part of release bookkeeping.
